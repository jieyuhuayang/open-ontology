# Open Ontology v0.2.1 — Workshop 体验改进决策记录

> **版本**: v0.2.1
> **日期**: 2026-03-26
> **性质**: v0.2.0 PRD 改进决策记录（非独立 PRD，详尽功能修改直接体现在 v0.2.0 PRD 中）
> **前置版本**: v0.2.0 — AI 辅助本体构建

---

## 一、改进背景与动机

v0.2.0 的 Workshop（本体工坊）已完成 F012-F017 的实现，但实际体验与产品愿景存在偏差。核心问题是**流程断裂**和**布局过早暴露**——用户第一次进入页面就面对复杂的三面板布局，而真正需要这些面板的时机是蓝图构建完成之后。

### 1.1 五个核心问题

| # | 问题 | 现状 | 期望 |
|---|------|------|------|
| 1 | **初始页面过于复杂** | 进入 `/workshop` 即显示三面板布局（Chat + Canvas + Sidekick），空白状态下引导卡片淹没在左侧面板中 | 首次进入只有**深色星空背景 + 居中全屏引导**，干净、沉浸、聚焦 |
| 2 | **文件上传时机断裂** | 领域引导和文件上传分属两个阶段：先填引导 → 再在 Chat 面板中上传素材 | 从领域引导开始就**引导用户上传文件**，引导和上传合为一体 |
| 3 | **Agent 自主构建缺乏仪式感** | 用户在 Chat 面板手动发消息触发分析，Agent 构建过程散落在对话和 Sidekick 之间 | 提交引导后 Agent **全自动构建**，这是 Workshop 最核心的功能点，配合全屏画布实时结晶动画展现过程 |
| 4 | **蓝图定义偏差 + Chat 面板定位模糊** | 蓝图被定义为一组"建议"，Chat 面板承担引导+上传+对话多重职责但定位不清 | 蓝图是**本体初稿**（Draft Schema），Chat 面板定位为**历史记录 + 蓝图调优**（Agent 提建议，用户 Accept/Edit/Reject） |
| 5 | **F018 Sidekick 独立且冗余** | Sidekick 作为 Ontology Manager 各页面的独立 AI 助手侧栏，与 Workshop 的 Agent 交互体系割裂 | **砍掉 F018**，将"Agent 提建议 + 用户 Accept/Edit/Reject"的能力合并到 Chat 面板的对话流中 |

### 1.2 核心理念校正

**之前**：Workshop 是一个"三面板工作台"，用户在其中完成从引导到构建到审查的全部操作。

**现在**：Workshop 是一个**分阶段的沉浸式体验**——从全屏引导（Phase 0）→ 全屏画布观看 Agent 构建（Phase 1）→ 两面板协作调优（Phase 2），每个阶段只展示该阶段需要的界面元素。

## 二、五项改进方案

### 2.1 改进一：全屏领域引导（Phase 0）

**目标**：用户进入 Workshop 的第一印象是**沉浸式引导**，而非复杂的工作台布局。

**设计**：
- 整个视口为深色星空背景（WorkshopCanvas 作为纯装饰背景，无交互节点）
- 居中放置 glass-morphism 风格引导组件（约 600px 宽）
- 引导组件内容（自上而下）：
  1. 欢迎标题 + 一句话说明
  2. 业务领域选择（pill grid，保留现有 6 个选项 + 自定义）
  3. 建模目标选择（pill grid，保留现有 5 个选项 + 自定义）
  4. 概念范围文本框（可选）
  5. **文件上传区**（拖放 + 点击上传，支持多文件，复用 FileUploadArea 组件）
  6. "开始构建" 按钮 / "跳过引导" 链接

**文件暂存策略**：引导阶段尚无 Agent Session，前端用 `useState<File[]>` 暂存文件对象列表。点击"开始构建"后：
1. 调用 `POST /api/v1/agent/sessions` 创建会话
2. 逐个调用 `POST /api/v1/agent/materials/upload` 上传暂存文件
3. 自动发送初始消息触发 Agent 构建
4. 页面过渡到 Phase 1

### 2.2 改进二：Agent 自主构建（Phase 1）

**目标**：这是 Workshop 最重要的功能——Agent 基于领域引导和上传素材，自主调用 skills 探索业务逻辑，形成本体初稿。这段过程可能较长（数十秒到数分钟），需要让用户清晰感知进展。

**布局**：全屏 3D 画布 + 底部浮动进度条 + 澄清交互浮层

- 画布占满视口，星体随 Agent 构建逐步"结晶"出现
- 底部浮动进度条：显示当前阶段名称 + 已识别实体/链接数 + 进度指示
- 左上角保留返回按钮
- **澄清交互**（保留 PRD 中的主动澄清机制）：Agent 遇到歧义时发送 `clarification-req` 事件，画布上弹出结构化选择题浮层，用户回答后 Agent 继续

**SSE 事件流**（复用现有类型）：
- `plan-step`：Agent 规划步骤 → 更新进度条阶段名称
- `blueprint-item`：每产生一个实体/链接 → 画布结晶动画 + 计数更新
- `clarification-req`：Agent 遇歧义 → 弹出选择题浮层
- `text-delta`：Agent 思考过程文本（在进度条中滚动显示或静默累积）
- `blueprint-complete`：构建完成 → 触发 Phase 1 → Phase 2 过渡动画

**Phase 1 → Phase 2 过渡**：
1. 进度条显示"构建完成！" + 短暂停留（~2s）
2. 进度条淡出
3. 左侧 Chat 面板从左侧滑入（CSS transition）
4. Chat 面板顶部自动填充：引导摘要 + 上传文件列表 + 构建过程摘要

### 2.3 改进三：重新定义"蓝图"

**之前**：蓝图是一组"建议"（BlueprintItem），每项附带置信度和来源标签，用户需在 Sidekick 审查表格中逐项 Accept/Edit/Reject。

**现在**：蓝图是**本体初稿**（Draft Schema）——语义上等同于 Ontology Manager 中尚未 Save 的本体状态，处于建 Schema 的阶段，还没有导入数据。

**关键语义变化**：

| 维度 | 之前（v0.2.0） | 现在（v0.2.1） |
|------|---------------|----------------|
| 蓝图本质 | 一组"建议"，待逐项审查 | 本体初稿（Draft Schema），可直接调优 |
| 蓝图项 | "建议"（suggestion） | 初稿中的实体/属性/链接 |
| 用户交互 | 审查表格逐项 Accept/Edit/Reject | 通过 Chat 对话自然语言调优，Agent 提建议时才触发 Accept/Edit/Reject |
| 审查入口 | Sidekick Review Tab + 底部审查栏 | Chat 面板中的建议卡片 |
| 完成标志 | 所有项审查完毕 | 用户满意后点击"应用到本体" |

**数据模型不变**：BlueprintItem 的 confidence/source/reasoning 等字段保留，用于：
- 画布上的视觉区分（高/中/低置信度的星体亮度和样式）
- EntityPopover 和 EntityDrawer 中展示推理来源信息
- Agent 内部决策参考

**状态机调整**：
- `draft` = Agent 正在构建（Phase 1）
- `pending_review` → 语义重映射为"就绪可调优"（Phase 2），前端文案不再显示"待审查"
- `applied` / `discarded` 保持不变

**布局**：两面板 — 左侧 Chat（380px, 可折叠）+ 中央画布（flex:1）。完全去掉右侧面板。

**Chat 面板两大功能**：

**功能一：历史记录展示**（面板顶部，可折叠）
- 引导阶段填写内容的摘要卡片（领域、目标、范围）
- 已上传文件的缩略卡列表
- Phase 1 Agent 构建过程的摘要

**功能二：蓝图调优交互**（面板主体）
- 用户发送自然语言指令，Agent 理解后执行 skill 修改蓝图
- **Agent 主动建议**：Agent 通过工具调用输出结构化建议，在消息流中以可交互卡片渲染
  - 建议类型举例：补充描述、创建新实体、创建链接、修改属性、合并重复实体
  - 每条建议卡片包含：摘要 + 详情（可展开）+ Accept / Edit / Reject 按钮
  - Accept → Agent 调用对应 skill 修改蓝图 → 画布实时更新星体
  - Edit → 展开内联编辑表单（复用 InlineEditForm）→ 修改后 Agent 执行
  - Reject → 建议标记为 rejected，卡片变灰
- 保留焦点锁定（FocusLockTag）、引导性提示气泡（PromptBubbles）
- 底部保留文件上传按钮（允许追加素材触发增量分析）

**"应用到本体"按钮**：位于画布工具栏中，替代原 Sidekick 中的"应用蓝图"按钮。点击后触发 ApplyProgressModal（保留现有的预检 + 应用 + 重试流程）。

### 2.5 改进五：砍掉 F018 独立 Sidekick

**F018 原定功能**：在 Ontology Manager 各页面（非工坊模式）提供常驻 AI 助手侧栏，包含规则建议（瞬时）和 LLM 语义建议（异步）。

**决定**：整体取消 F018，不做独立 Sidekick。

**能力迁移**：
- F018 中有价值的规则建议逻辑（如"对象类型缺少描述"、"建议添加链接"、"同名属性可合并"等）→ 提取为 Agent skill `suggest-improvements`
- Agent 在 Workshop Phase 2 对话中主动调用此 skill，输出结构化建议
- 建议交互（Accept/Edit/Reject）在 Chat 面板消息流中完成
- 从实现角度，Agent 提建议通过**工具调用**（tool_use）实现，SSE 适配器新增 `suggestion` 事件类型

**删除范围**：
- 后端：`sidekick_service.py`, `sidekick_rules.py`, `sidekick_llm.py`, `routers/sidekick.py`
- 前端：`SidekickPanel.tsx` 及其子组件（PlanProgressTree 移到 Phase 1 进度条，SuggestionCard 移到 Chat 消息流）
- release-contract.md 中 F018 标记为 `cancelled`

## 三、影响评估

### 3.1 受影响的 Feature

| Feature | 影响程度 | 说明 |
|---------|---------|------|
| F012 Agent Foundation | 无 | 底层引擎不变 |
| F013 CLI & Skills | 小 | 新增 `suggest-improvements` skill |
| F014 Material & Blueprint | 无 | 数据模型不变，仅语义重映射 |
| F015 Workshop Foundation | **大** | 布局重写，Phase 状态机 |
| F016 Workshop Enhancement | 小 | 画布交互保留，调整触发时机 |
| F017 HITL Review & Apply | **中** | 审查交互从表格迁移到 Chat 建议卡片 |
| F018 Agent Sidekick | **取消** | 整体砍掉，能力迁移 |
| F019 Import/Export | 无 | 不受影响 |

### 3.2 后端影响

- **无需新 API 端点**：复用现有 chat/materials/blueprints API
- **新增 SSE 事件类型**：`suggestion`（Agent 工具调用输出建议时推送到前端）
- **新增 Agent Skill**：`suggest-improvements`（从 F018 规则逻辑提取）
- **Agent 系统 prompt**：增强 `ontology_builder.md`，支持蓝图完成后主动分析并提建议
- **Blueprint 状态机**：保守方案，不修改枚举值，仅前端重映射语义

### 3.3 不变量兼容性

所有现有不变量（INV-10 ~ INV-16）保持有效：
- INV-10（Blueprint 必须 pending_review 才能 apply）→ 不变，前端仅重映射文案
- INV-11（userDecision 不可逆）→ 不变
- INV-13（文件限制）→ 不变
- INV-15（Apply 顺序 OT→Property→LT）→ 不变
- INV-16（BlueprintItem 必须有 source）→ 不变

## 五、v0.2.0 PRD Review 检查记录

### 检查 #1 — 主题：Phase 0 全屏引导（改进一）（2026-03-26）

**检查范围**：Phase 0 引导页、文件上传与引导合一、旧流程残留引用

**发现并修复的问题**：

1. **§4.3 升级对比表残留旧描述**：`蓝图审查 → 底部审查栏 + 内联编辑` 未更新 → 已修改为 `Chat 面板建议卡片（Accept/Edit/Reject）+ 自然语言对话`
2. **页面状态表缺少"已有本体"场景**：旧版有 `已有本体` 状态（渲染现有 OT + "扩展本体"引导），新版的状态表遗漏了此入口 → 已补充 `existing` 状态行 + 状态进入逻辑说明

**结论**：Phase 0 相关内容已修改到位。
